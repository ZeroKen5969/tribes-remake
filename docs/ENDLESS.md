# 無盡模式

無盡模式的世界沒有邊界：土地在部落需要時才產生，產生的地形照原版十張地圖的樣子拼出來；電腦部落的數量沒有上限，開局之外還會在新開出的土地上陸續出現；部落被消滅不會結束遊戲。規則在 `src/Tribes.Core`（`Systems/Endless`、`Maps/Generation`），所有數字在 `data/endless/endless.json`。

## 開始

- `GameSimulation.StartEndless(content, EndlessSetup)`：

| 欄位 | 意思 |
|---|---|
| `Seed` | 世界種子：土地、棲地、新部落與規則的亂數都由它來 |
| `Difficulty` | 電腦部落的難度（0 簡單、1 困難）：開局的、排隊的與之後出現的電腦部落都用它（電腦部落數量沒有上限，所以是全部一個設定） |
| `Tribes` | 列出的部落（真人依欄位順序；至少一個，也可以列電腦） |
| `ComputerTribes` | 開局再加的電腦部落數，不限；前 `camps.placedAtStart`（32）個開局就有營地，其餘排隊等候（見「新的電腦部落」） |
| `NewTribes` | 新電腦部落出現的密度：0 不出現、1 少、2 一般、3 多 |
| `StartAreaSize` | 開局在 (0, 0) 周圍先產生的範圍（格，邊長）；0 用規則預設 128 |
| `HintsEnabled` | 真人部落開局是否開著提示 |
| `Settings` | 世界設定（`WorldSettings`）：開局保護的幀數、起始資源（地圖原本的百分之幾）、有沒有野生動物；不給時用規則預設（開局保護 `pacing.openingGraceFrames`，資源 100%，有動物） |
| `DevAllianceHalls` | 測試腳本用：真人部落開局就有蓋好的聯盟建築與 300 木頭、300 石頭 |

- 世界照第一張自訂地圖的任務規則（關卡 7，`endless.json` 的 `mission`）：單位、建築、解鎖、電腦的建造計畫與兵種、動物種類都用它；地圖則是產生的。
- 每個部落都得到一個營地（酋長小屋、倉庫、成年人），營地原點彼此至少相距 `camps.minimumDistance`（40 格）。真人部落的營地先放，再放電腦部落；附近放不下就往外產生土地，直到放得下。
- 世界永遠不會分出勝負（`Match.EndsWithLastSide` 關閉）；部落被消滅只是出局（`TribeOut`）。

## 座標與區塊

- 格子座標可以是負數，土地往四面八方長。區塊是 64 × 64 格，`ChunkCoord.Of(格)` 以向下取整算出（`格 >> 6`）。
- `WorldMap.IsChunked` 為真；`Bounds` 是已產生區塊的外框，框內還沒產生的格子讀起來是 `WorldMap.UngeneratedTile`（255，擋路、沒有圖）與 `Impassable`。
- 規則對座標不做位元組截斷，方向與距離在任何座標都對；超過 95 格遠的目的地分段規劃路線（走到半路再重新規劃）。

## 土地怎麼產生

- 每 `land.checkEveryFrames`（8）幀檢查一次：任何部落的單位或建築周圍 `land.reachCells`（48）格內有還沒產生也還沒在做的區塊，就把它排進產生的佇列，同一次排入的依列由上而下、每列由左而右。
- 佇列裡的區塊在另一條執行緒上設計（一次一塊，照排入的順序），在排入後 `land.leadFrames`（24）幀加入世界，而且一幀最多加入一塊；到了那一幀還沒設計好，這一幀就等它。區塊長成什麼只看排入當時的世界狀態（已有鄰居的邊緣，或佇列裡較早那塊的設計），所以所有裝置、以及中途存檔再讀檔的世界，都在同一幀得到同樣的土地。存檔帶著佇列（每塊的位置、加入的幀、當時的邊緣）。
- 開局的土地、在邊界找營地時、以及 `GenerateLand` 會立刻產生（先讓佇列裡的區塊全部加入）。
- 還沒產生的格子讀起來擋路，單位不會走進去。
- 區塊的種子是 `hash(世界種子, 區塊 x, 區塊 y)`；已經存在的鄰居區塊的邊緣是限制條件，所以接縫看不出來。
- 地形的做法：
  1. 從原版十張地圖的設計（變體之前的圖塊）學出：每種圖塊在上下左右可以接哪些圖塊、每對相鄰出現幾次、每種圖塊用了幾次。
  2. 區塊切成 4 片 32 × 32，依序從原版地圖隨機挑一片，挑四邊最能接上已經放好的片與鄰居區塊的；一樣能接上的幾片裡，挑資源點數量最接近原版平均的。
  3. 接不上的地方（片與片之間、與鄰居區塊之間）連同周圍幾格重新解：每格只留下能和四周相鄰的圖塊，選項最少的格先決定，依它和已決定的鄰格在原版中相鄰的次數抽；走不下去就退回前一個選擇改選別的。範圍逐步加大，最後整塊重解。
  4. 補資源點：每種資源點補到原版地圖的平均數量（每塊區塊依原版十張地圖的比例），只放在沒有鎖定的平地上，四周都要能照原版規則接上，而且區塊仍然連通。
  5. 和 `MapBuilder` 一樣建出格子：隨機變體、擋路地形、岩石、樹叢、資源點，以及資源點旁的岸邊（跨區塊邊緣也算）。
- 連通：每個區塊四邊正中各有 8 格的連接口（第 28～35 格），四個角各 1 格，都是平地；兩個相鄰區塊的連接口剛好相接。區塊內四個連接口一定以可走的格子（上下左右相連）連在一起：拼出來沒連上時，挖一條最少破壞的平地小路（不挖區塊邊緣）再修接縫。所以整片已產生的土地是連通的，營地與邊界都走得到。
- 每個區塊記著產生它的產生器版本（`MapChunk.GeneratorVersion`，現在是 1）。存檔保存每個已產生的區塊與完整狀態，不只是種子；之後就算產生器改了，已經有的地形也不會變，新區塊照當時的產生器做、以存好的鄰居邊緣為限制。

## 營地

- 營地範圍是營地的建築與單位，外加 `camps.siteMargin`（1）格。範圍內每格都得是可走的平地，或只有樹叢、岩石、資源點這類會被清掉的東西，且沒有單位、動物、建築；範圍要碰到該區塊裡和連接口連通的地面。
- 候選原點每 `camps.candidateStep`（4）格一個；從起點一圈一圈往外找第一個有空位的區塊，在區塊內選離最近營地最遠的位置。放營地前清掉範圍內的樹叢、岩石與資源點；清掉的格子換成和四周圖塊接得起來的平地圖塊（依原版地圖學到的相鄰規則挑）。
- 中途用 `AddTribe` 加入的部落（真人或電腦）也這樣找：已產生的土地都沒有空位時，就在邊界產生新區塊再找，所以 `AddTribe` 在無盡世界一定成功。

## 新的電腦部落

- 開局要的電腦部落超過 `camps.placedAtStart`（32）個時，多出來的排隊等候（`World.Endless.WaitingTribes`），所以要多少個都能立刻開局。真人部落的單位或建築帶出來的新區塊，每塊先讓一個排隊的部落進來；它以世界的難度遊玩。
- 這些新區塊每塊依自己的種子抽一次：密度 1、2、3 時約每 8、4、2 塊有一個新部落（`newTribes.chunksPerTribe`）。抽中的部落也加入排隊，所以抽中的區塊放不下營地時，它在之後第一個放得下的區塊出現（大約一半的區塊沒有放得下整個營地的地面）。新部落也以世界設定的電腦難度遊玩。
- 排隊的與新的部落，營地都要在那個區塊內，離所有營地至少 40 格、離每個真人部落的營地至少 `newTribes.distanceFromPeopleCamps`（40）格；`newTribes.distanceFromPeople` 是離每個真人單位的最短距離（0 表示不限制）；放不下就等下一塊。在區塊裡，離最近營地 1.5 倍營地間距以內的位置越遠越好，更遠的都一樣，再挑最靠近區塊中央的。
- 電腦部落的單位與建築帶出的土地不會讓部落進來；真人不探索，排隊的部落就一直等。

## 電腦部落的節奏（`pacing`）

| 規則 | 數字 |
|---|---|
| 開局保護：直到世界設定的開局保護結束，電腦部落不出兵打任何部落，也不追趕走進牠們領地的人；電腦的升溫從保護結束才開始算 | 預設 `openingGraceFrames` 7500 幀（正常速度 15 分鐘），大廳可改 |
| 新來者保護：後來加入或出現的部落在 `newcomerGraceFrames` 幀內不會被打；新出現的電腦部落同樣時間內不出兵 | 7500 幀 |
| 只打營地相距 `attackReachCells` 格以內的敵人 | 192 格 |
| 只打活著的成年人不超過自己 `strengthPercent` 的敵人 | 150% |
| 同時對同一個部落出兵的電腦部落最多 `attackersPerTarget` 個 | 2 |
| 範圍內的真人優先：營地相距 `humanReachCells` 格以內、可以打的真人部落，不論有沒有更近的敵人，電腦都先挑它；有好幾個時挑目前被最少電腦部落攻擊的，再挑近的、編號小的。範圍內沒有真人時，照對戰的挑法（最近的敵人 1.5 倍距離內、成年人最少的）。0 表示不使用 | 120 格 |

- 電腦部落之間互為敵人，保護結束後也會互打。
- 電腦的升溫（進攻波人數成長、出兵前的等待、陷阱與法術開始的時間）從部落加入的那一幀起算，所以新部落從弱開始。
- 電腦的定期檢查（找入侵者、進攻波的推進、建造計畫與修理、武器庫訂單、法術）依部落編號錯開：第 n 個部落的時間表往後移 7n 幀，所以幾十個電腦部落輪流檢查，不會擠在同一幀。
- 電腦只防守營地 20 格內（營地間距的一半）、而且比其他任何營地都近至少 4 格的格子，不是原版任務裡電腦那半張地圖；別人的營地與他那一側的土地永遠不在電腦的防守範圍裡。保護期間連這片土地也不追趕。
- 每個營地在自己這一側、營地 40 格內（營地間距），都放得下 12 個 3 × 3 的建築位置（彼此留一格路）；一個區塊裡最好的幾個營地位置都沒有這麼多空間時，部落改去別的地方。

## 野生動物

- 每個新區塊依自己的種子平均有 `wildlife.habitatChancePercent`（150）÷ 100 個棲地：每滿 100 一個，剩下的是多一個的機會（150 就是一個，加上一半機會再一個）。每單位面積的棲地數和原版自訂地圖相近。棲地的動物種類照某張自訂地圖的某個棲地。
- 生育照任務規則的間隔；只有離某個還在場部落的營地、或離某個真人單位 `wildlife.activeDistance`（128）格以內的棲地會生，每次每兩個這樣的棲地生一隻（和原版一張地圖約兩個棲地生一隻相同），每個棲地最多 `wildlife.animalsPerHabitat`（3）隻。會攻擊人的老虎（`wildlife.fierceKind`，1）只保留原本機率的 `wildlife.fierceSharePercent`（33%），其餘改生其他動物；只生老虎的棲地那次就不生。這條在對戰也適用，戰役照原版。動物在棲地附近遊蕩。動物不會在任何營地周圍 20 格內出生（棲地離營地太近時改生在這範圍外最近的空格）；世界設定關掉野生動物時不會出生。
- 動物的格位會隨需要增加（原版 22 個）。

## 聯盟

- 聯盟建築（建築種類 26，`AllianceBuilding.Kind`）：3 × 3，工地是 3 × 3 的工地；造價 30 木頭、30 石頭，80 點耐久；每個部落一棟，沒有升級與修理，單位不會進去。只在無盡世界的建造選單裡（`OrderMenus.BuildableKinds` 的最後一項）。
- 指令（都會檢查，不合就不執行，也不會丟出例外）：

| 指令 | 條件 |
|---|---|
| `InviteAlly(部落, 對象)` | 自己有蓋好的聯盟建築；對象是另一個真人部落，玩家正在遊戲中（不是離線、已放棄或出局）；雙方還不是盟友；之間沒有未回覆的邀請 |
| `AnswerAlliance(部落, 邀請者, 接受)` | 有邀請者給自己的未回覆邀請；接受後雙方立刻成為盟友 |
| `LeaveAlliance(部落, 盟友)` | 雙方是盟友；離開後回到敵對 |
| `TransferGoods(部落, 盟友, 貨物, 數量)` | 雙方是盟友、都還在場、都有蓋好的聯盟建築；貨物是糧食、食物、木頭、石頭、骨頭或武器之一；1 ≤ 數量 ≤ 自己的存量；對方最多收到存量上限 999，自己只扣掉實際送出的量 |

- 邀請在 `alliance.invitationFrames`（1500）幀後失效；被邀請的人離線、出局，或邀請者出局時也失效。
- 一方出局（被消滅或放棄）的那一幀，聯盟自動結束：發出 `AllianceEnded`，`By` 是出局的部落，雙方回到敵對。
- 盟友互不攻擊、互不傷害，陷阱不會抓盟友；結盟的那一刻，正在攻擊對方的單位會停下。
- 視野：結盟期間雙方共享視野（見下）。
- 事件：`AllianceInvited`、`AllianceDeclined`、`AllianceInvitationLapsed`、`AllianceFormed`、`AllianceEnded`、`GoodsTransferred`；另有 `ChunksGenerated`（新土地）與 `TribeAppeared`（部落得到營地）。

## 視野

無盡世界與多人對戰的規則相同：盟友（同一隊，或在遊戲中結盟）共享視野。

- 看得到：每個部落除了自己單位與建築看到的地方，也看得到盟友的單位與建築現在看到的地方（電腦盟友也算）。只算盟友自己看到的，不會經由盟友的其他盟友再轉過來。
- 探索過的土地：結盟的真人部落共用探索過的土地；盟友從它的其他盟友得知的土地也一起共用。
- 聯盟結束後：已經探索過的土地仍是探索過的；即時的視野在下一次視野更新（半秒內）停止共享。
- 規則裡用到視野的地方都算盟友給的視野：下指令選目標、看得到的敵人才打得到、蓋建築的位置必須在視野內、路線規劃把探索過的土地當成已知。電腦部落沒有迷霧，不受影響。
- 觀戰的人看到所有真人玩家（含離線、已放棄的）視野的聯集；電腦部落看到的地方，只有它是某個真人玩家的盟友時才看得到。
- 打仗的敵人：敵方單位攻擊自己（或自己的電腦盟友）時，牠站的地方看得到；真人盟友被攻擊時，由盟友的視野帶過來。別的部落之間打仗看不到。戰役照原版：攻擊中的敵人都看得到。
- 建築的記憶：每個真人部落記得看過的建築最後的樣子（種類、等級、工作、耐久）。視野外的地方只畫記得的樣子：之後才蓋的看不到，被摧毀的仍留著，直到再看到那個地方；盟友共用記得的建築（以較晚看到的為準），觀戰者看到真人玩家記得的（以最晚看到的為準）。盟友在結盟前就看到某棟建築已經不在了，自己的舊記憶仍會留到有人再看到那裡。戰役照原版：探索過的地方畫建築現在的樣子。

## 存檔

- 世界快照格式 3 起：地圖種類（固定或區塊）、每個已產生的區塊（座標、產生器版本、每格圖塊一個位元組、格子內容以連續相同的段落存）、無盡狀態（種子、密度、排隊的電腦部落數、棲地、未回覆的邀請、產生中的區塊）與各部落加入的幀。格式 4 加上世界設定。格式 5 存每個單位與建築格位屬於哪個部落、每張會增加的表格（工地、升級與修理、陷阱訂單、塵埃、情侶、區段索引，與各部落的軍械庫佇列、工作指令）的長度，以及世界有沒有上限。格式 6 存每個部落自己的安靜時間（多久沒打仗），更早的存檔讀進來時每個部落都從世界的計數接著數。格式 7 存每個部落記得的建築（見「視野」）；更早的對局存檔讀進來時，每個真人部落記得它探索過的土地上當時的建築。讀得了格式 1～7；格式 4 以前的對局與無盡世界讀進來時，格位與表格照當時的大小（每個部落 50／30 個格位，表格隨部落數加大），之後隨需要增加。
- 部落沒有單位與建築上限，格位與表格隨需要增加（見 [RULES.md](RULES.md)「對戰、自訂遊戲與無盡模式不限單位與建築」）。
- 狀態雜湊：地圖的雜湊隨格子改變即時更新，雜湊時不必逐格走過；迷霧每個區塊記一個摘要，只有改過的區塊重算；其他狀態每個值一次乘法混入。

## 效能

桌機，最佳化組建，同時有其他測試在跑：

| 量測 | 數字 |
