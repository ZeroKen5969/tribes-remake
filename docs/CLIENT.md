# 用戶端

Godot 4.7.2 .NET 用戶端在 `client/`。本文件說明選單、設定與它們交給對局畫面的資料。

## 選單與設定

### 畫面

| 畫面 | 場景 | 內容 |
|---|---|---|
| 開機 | `scenes/ui/boot.tscn`（主場景） | 原版標題圖置中，四周依原圖的天空、雲、丘陵、樹叢與草地延伸到填滿畫面；同時載入介面圖案、主題與遊戲資料，開始播放選單音樂，再進主選單。下載過的內容包在這之前就已掛上。遊戲資料先複製到 `user://content/<內容雜湊>/` 再讀：每份內容一個資料夾、裡面只有這份內容的檔案，其他版本留下的資料夾會刪掉，所以更新後拿掉的檔案（例如地圖）不會再被讀到；同一台電腦同時開好幾個遊戲也不會互相干擾 |
| 主選單 | `scenes/ui/main_menu.tscn` | 原版標題畫面：營地與三個村民站在畫面底邊，兩側接原版地形的樹林，上方是飄著原版雲朵的天空；標誌與羊皮紙選單放在天空裡，不擋住營地。選單：戰役、自訂遊戲、多人對戰、無盡模式、讀取進度、設定、檢查更新、製作名單、離開（只在 PC） |
| 設定 | `scenes/ui/settings.tscn` | 見下方「設定」 |
| 戰役 | `scenes/ui/campaign.tscn` | 跟原版關卡選單一樣列出 5 關：第 1 關 走出洞穴（附教學）、第 2 關 復仇、第 3 關 逃脫、第 4 關 荒原、第 5 關 新家園。贏過的關打勾，還沒開放的關上鎖。選關後顯示該關的原版劇情插圖與開場劇情文字，選難度（簡單／困難）後開始 |
| 自訂遊戲 | `scenes/ui/custom_game.tscn` | 原版的五張自訂地圖：大湖、沙漠隘口、森林地帶、大屠殺、一方土地（附小地圖預覽、大小與最多幾個部落）、難度、部落顏色；對手是一個電腦部落 |
| 多人對戰 | `scenes/ui/multiplayer.tscn` | 「區域網路」分頁：自動搜尋同一網路的房間（包括對局中的房間，見下方「房間清單」）、建立房間、輸入位址加入。「網際網路」分頁：經 Photon 的雲端伺服器列出一個地區的房間（同樣的房間清單）、選地區（預設最近的地區）、建立對戰或無盡房間、輸入房間代碼加入（見下方「網際網路房間」） |
| 房間 | `scenes/ui/lobby.tscn` | 4 個部落欄位、自己的顏色與隊伍、準備、聊天；主機另可選地圖、電腦難度、加入／移除電腦部落、請人離開、開始 |
| 無盡模式 | `scenes/ui/endless.tscn` | 新世界（世界種子、起始區域大小、起始電腦部落數〔沒有上限〕、電腦難度、世界擴大時新部落出現的多寡、開局保護、起始資源、野生動物）、繼續存檔（每個存檔列出世界名稱、存檔與遊玩時間、世界設定那一行，見「讀取進度」）、在區域網路開放房間讓朋友加入 |
| 讀取進度 | `scenes/ui/load_game.tscn` | 所有模式的存檔（自動存檔與手動存檔），新的在前：縮圖、模式與關卡名稱、欄位、存檔時間、遊玩時間；有世界設定的存檔（對戰、自訂遊戲、無盡模式）多一行「電腦：簡單・保護 15 分鐘・資源 ×1・有野生動物」（`SaveSettingsText`，窄的時候只在兩項之間換行），戰役與舊版的存檔沒有這一行；可讀取或刪除。沒有縮圖或讀不出來時顯示一張淡色風景圖代替。讀取主機的多人存檔時先問在「區域網路」或「網際網路」重新開房（這個建置能開網際網路房間時） |
| 檢查更新 | `scenes/ui/update.tscn` | 檢查 → 版本與更新說明 → 下載進度 → 套用；錯誤顯示 `UpdateException.UserMessage`（流程見 [UPDATES.md](UPDATES.md)） |
| 製作名單 | `scenes/ui/credits.tscn` | 原版與重製版名單，以及第三方授權（Godot、.NET、Cubic 11、FluidR3_GM、MeltySynth、OggVorbisEncoder），可展開授權全文 |

- 畫面以邏輯像素排版，整數倍放大（`GameApp`）：短邊至少 340 邏輯像素。視窗不是倍率的整數倍時，最後一個邏輯像素只露出一部分，任何大小都填滿視窗、沒有黑邊；改變視窗大小時倍率與版面立即重算。
- PC 可以全螢幕：設定的「畫面」（視窗／全螢幕），或在任何畫面按 F11、Alt＋Enter 切換（`GameApp._Input`，在介面元件之前接到，Enter 不會按到選到的按鈕），選擇存進設定、下次開遊戲照樣。全螢幕是 Godot 的無邊框全螢幕（`Window.ModeEnum.Fullscreen`，桌面的解析度、不換顯示模式），切到別的視窗不必換螢幕模式；回到視窗時恢復原本的視窗（含最大化）。切換時視窗大小改變，畫面照上一條重新排版。開發用的 `--ui-window`、`--resize-to` 時不套用全螢幕。
- 直向與橫向都可用，直向時兩欄的畫面改成上下排列，戰役的關卡清單與簡報改為分頁切換。
- 所有畫面的按鈕都排在螢幕的安全範圍內（`GameApp.SafeMargins`，邏輯像素）：避開瀏海與挖孔（手機回報的安全區域，`DisplayServer.GetDisplaySafeArea`），避開圓角（Android 12 起由 `ScreenCorners.java` 讀出每個角的圓弧，按鈕的角要落在圓弧內，大約留圓角半徑的 0.29 倍，`SafeMargins.ForCorners`），再加上設定的「螢幕邊緣留白」；轉向後 0.3 秒、1 秒再重讀一次。地圖、背景與劇情的黑邊仍鋪滿整個螢幕。PC 與沒有瀏海、圓角的手機不留邊。
- 畫面放不下內容時（例如手機上把介面大小調大），標題下面的內容整頁可以上下捲動，太窄時也可以左右捲動，頁面裡的清單至少保留 72 邏輯像素高；畫面放得下時版面和沒有捲動時一樣。主選單一欄排不下時排成兩欄。
- 觸控螢幕上，清單從按鈕或框起來的一列上開始拖曳也能捲動（`TouchScrolling`：清單裡的按鈕與面板把按下也交給清單；清單開始捲動時放開手指起頭的那個按鈕，所以拖曳不會按到它）；手指移動 10 邏輯像素以內仍算點擊。
- 觸控、滑鼠、鍵盤都能操作：一般按鈕至少 24 邏輯像素高；方向鍵與 Tab 移動焦點；Esc 或 Android 返回鍵回到上一層，主選單上會詢問是否離開。
- 開始對局後切到對局畫面（見下方「對局畫面」）。

### 設定

存在 `user://settings.json`，每改一項就立即存檔並生效。

| 欄位 | 畫面上的名稱 | 說明 |
|---|---|---|
| `Language` | 語言 | `zh-TW`（預設）或 `en`，切換後所有畫面立即換語言 |
| `MusicVolume` | 音樂音量 | 0～1，立即套用；0 時音樂暫停 |
| `EffectsVolume` | 音效音量 | 0～1，立即套用（改的時候播一聲試聽）；0 時不出聲 |
| `InterfaceScale` | 介面大小 | 1 標準、2 大、3 特大：在自動倍率上再放大，但短邊至少保留 200 邏輯像素 |
| `EdgeMargin` | 螢幕邊緣留白 | 無、小、中、大、特大（0、6、12、18、24 邏輯像素，`SafeMargins.PlayerChoices`）：在瀏海與圓角需要的留白之外，所有畫面的按鈕再離螢幕邊緣這麼遠，立即套用；只在觸控螢幕顯示，預設無 |
| `ShowHints` | 遊戲中顯示提示 | 傳給對局 |
| `Tutorial` | 前幾關顯示教學說明 | 傳給對局 |
| `EdgeScroll` | 滑鼠碰到視窗邊緣時捲動畫面 | 只在 PC 顯示 |
| `Fullscreen` | 畫面：視窗／全螢幕 | 只在 PC 顯示，預設視窗；F11、Alt＋Enter 也會改它 |
| `ShowPlayers` | 多人對局中顯示玩家清單 | 預設顯示；對局裡的清單按鈕與 Tab 也會改它 |
| `UnitCardDetailed` | 村民面板顯示技能 | 預設不顯示；選取面板的技能按鈕與對局裡的設定也會改它，立刻生效 |
| `SelectionPanelFolded` | （設定畫面沒有）選取面板收成小標籤 | 選取面板的 －／＋ 改它 |
| `TaskIcons` | 任務圖示：全部村民／選取的村民／不顯示 | 原版的「資訊：全部／已選取／無」；預設選取的村民（用滑鼠時加上指著的）；對局裡的設定也能改，立刻生效 |
| `PlayerName` | 玩家名稱 | 最多 24 字，房間裡其他人看到的名字 |
| `PlayerId` | — | 不顯示。連線用的秘密金鑰，重連時靠它認人 |

### 文字與語言

- 介面文字都是鍵（例如 `menu.campaign`），由 Godot 的 `TranslationServer` 翻譯，換語言時標籤與按鈕自動更新。
- 新介面的文字：`data/client/strings/ui.zh-TW.json`、`ui.en.json`，格式 `{"format": "tribes-ui-strings/1", "language": "zh-TW", "strings": {"鍵": "文字"}}`；`{0}`、`{1}` 是執行時代入的值。英文缺少的鍵會顯示繁體中文。
- 原版字串（`data/client/strings/zh-TW.json`、`en.json`）同樣登錄成鍵：`s.N`（表 s）、`t.N`（表 t）、`d.N`（劇情頁，N＝71＋頁碼）。關卡名稱取 `s.82` 起（依原版關卡選單順序），簡報文字取各關開場劇情的頁面。原版英文字串存成小寫，顯示時名稱改成字首大寫、劇情改成句首大寫。
- 字型一律用 Cubic 11（12 與 24 像素，關閉反鋸齒）；原版點陣字（只有英文字母與數字）以 `OriginalLabel` 樣式提供。

### 介面圖案與主題

- `PixelTheme` 在開機時用原版的介面圖件組出 Godot 主題：選單的撕邊羊皮紙（精靈 1656）、圖示列格子（548、549）、確認勾與取消叉（部件 1506、1509）、選單箭頭（特效 1、2）；原版沒有的元件（按鈕各狀態、輸入框、捲軸、滑桿、勾選框、分頁、提示框、進度條、鎖頭）以同一組調色盤與框線畫法繪製。
- 樣式變化：`SheetPanel`、`InsetPanel`、`SlotPanel`、`SlotSelectedPanel`、`BubblePanel`、`VeilPanel`（容器）；`MenuItemButton`（主選單項目：大號黃字，被選到時兩側出現原版的動畫箭頭）、`PrimaryButton`、`ToolButton`（按鈕）；`TitleLabel`、`HeadingLabel`、`MutedLabel`、`OnDarkLabel`、`OriginalLabel`（標籤）。主題套在根視窗上，所有畫面共用。
- 部落顏色讀 `data/client/tribe-colours.json`（8 色，`name` 繁中、`nameEn` 英文、`swatch` 顯示色）；檔案不存在時顯示編號的暫代顏色。

### 戰役進度與存檔

- 戰役進度：`user://progress.json`，`{"format": "tribes-progress/1", "completed": [0, 1], "difficulty": 0}`。對局勝利後呼叫 `CampaignProgress.MarkCompleted(關卡)`。
- 戰役清單（`CampaignChapters`）照原版關卡選單：`missions-rules.json` 的 `menuMissions` 裡第 7 關之前的項目（0、2、3、4、5）各是一關，名稱是原版字串 s.82 起依選單順序。兩個起點之間的關卡（1、6）接在前一個起點之後、在同一個世界裡玩下去，不單獨列出，名稱也沿用所屬那一關。
- 一關的最後一個關卡贏過（`completed` 有它）就打勾，例如第 1 關要贏過關卡 1、第 5 關要贏過關卡 6。開放到「贏過的最後一關」的下一關為止，跟原版選單一樣。
- 「開始」一律從那一關的起點開始（關卡 0、2、3、4、5）。
- 選單項目從第 7 關起（7～11）是自訂地圖，也用在多人房間的地圖清單。關卡 7 的開場對話是戰役的結尾劇情（對話 59），但結尾不開關卡 7：第 5 關的後半段（關卡 6）贏了之後，劇情在同一個世界裡播（見下方對局畫面的「戰役、存檔」）。
- 存檔：`user://saves/<模式>-<欄位>.save`（對局層自己的格式）加上說明檔 `<模式>-<欄位>.json`。模式為 `campaign`、`custom`、`versus`、`endless`，欄位為 `auto` 或 `1`～`5`。說明檔欄位：`format`（`tribes-save-info/1`）、`mode`、`slot`、`mission`、`difficulty`、`savedAt`（UTC）、`playSeconds`、`title`（無盡世界名稱等，可空）、`settings`（世界設定：`openingGraceFrames`、`startStockPercent`、`wildAnimals`；戰役與舊版存檔沒有）。寫入用 `SaveCatalog.Write(info, data)`。
- 讀取進度畫面的縮圖是存檔旁同名的 `.png`（`SaveCatalog.ThumbnailPath`，由對局畫面寫入）。檔案要是完整的 PNG（開頭的檔頭、結尾的 IEND）、長寬在 1～1024 之間、不超過 1 MB 才會讀，否則顯示代替圖（`SaveThumbnails`、`SaveThumbnail`）。每列寬度至少 440 邏輯像素時縮圖以原尺寸 160×90 顯示，較窄（直向手機）時縮成 80×45，讀取與刪除按鈕改成上下排。

### 開始對局

選單把要求放在 `GameApp.Instance.Match`（`MatchRequest`），再切到 `UiScreens.Match`（`res://scenes/match/match.tscn`）：

| 欄位 | 說明 |
|---|---|
| `Mode` | `Campaign`、`Custom`、`Versus`、`Endless` |
| `Mission` | 關卡編號（`missions.json`）；無盡世界為 -1 |
| `Difficulty` | 0 簡單、1 困難 |
| `Tutorial`、`ShowHints` | 來自設定 |
| `Players` | 每個部落：欄位、名稱、是否電腦、顏色（-1＝關卡預設外觀）、隊伍、電腦強度、是否由這台裝置操作 |
| `Session` | 多人對局的連線（`HostSession` 或 `ClientSession`，已在對局階段）；單人時為 null。對局畫面接手後每幀呼叫 `Update()`；關閉主機的連線後呼叫 `MulticastLease.Release()`（Android 的多播鎖） |
| `SaveToLoad` | 要讀取的存檔路徑；新對局為 null |
| `Endless` | 新無盡世界的種子、起始區域大小、起始電腦部落數（沒有上限）、新部落出現的多寡（0 不再出現、1 偶爾、2 持續、3 大量）。新無盡世界的 `Players` 只列真人 |

- 多人房間的模擬由 `MatchSimulations.Factory` 建立；對局層把它換成規則模擬。主機開始時送出的開局資料是 UTF-8 JSON：`{"mission": 8, "difficulty": 0, "seed": 1234, "endless": null}`，無盡模式的 `endless` 為 `{"seed", "startAreaSize", "computerTribes", "newTribes"}`（`MatchSetup`）。

### 多人房間

- 區域網路：TCP 47801 連線、UDP 47800 找房（[NETWORK.md](NETWORK.md)）。主機的房間資訊列出別人可輸入的位址；Windows 第一次建立房間時防火牆可能詢問，要允許才能讓其他電腦加入。Android 搜尋房間時會取得 Wi-Fi 多播鎖。
- 每房最多 4 個部落（真人與電腦共用）。8 種顏色同房不重複：別人用掉的顏色顯示紅叉、不能選；兩人同時選同一色時後到的人會看到「這個顏色已經有部落使用了」。
- 欄位狀態：主機、已準備、尚未準備、遊戲中、電腦（附難度）；斷線的玩家顯示「離線」。
- 開始條件：所有真人都按了準備，對戰模式至少 2 個部落、2 個隊伍。
- 地圖容量：每張自訂地圖最多能放的部落數（真人與電腦合計）是規則找得到的營地數（`MatchStart.CampCapacity`）：大湖 10、沙漠隘口 20、森林地帶 9、大屠殺 8、一方土地 7。主機選地圖時下方顯示這個數字；地圖滿了，空位就顯示「地圖已滿」、不能再加電腦；部落比地圖能放的多時「開始對戰」不能按，並說明要移除幾個部落（`MatchRoom`、`MissionCatalog.TribeLimit`）。目前房間最多 4 個部落，小於每張地圖的容量。每張地圖的容量要排一次整個世界的營地（一張最多約 0.2 秒），所以開機後在背景一次算好、之後沿用（`MissionCatalog.PrepareCapacities`）；還沒算好時房間顯示「正在計算這張地圖能放幾個部落……」，「開始對戰」暫時不能按，算好後自動更新。
- 房間只提供自訂地圖，不提供戰役地圖（戰役地圖只有原版的兩個部落）。無盡模式沒有部落數上限。
- 無盡模式的房間由主機選世界：起始區域、起始電腦部落數（沒有上限，任何放得下的非負整數；規則一開始先安置一部分，其餘隨著玩家開出新土地陸續出現；另外加在欄位裡的電腦部落之外）、世界擴大時新部落出現的多寡，與單人無盡模式的選項相同（`EndlessOptions`）；按鈕是「開始遊戲」。主機的設定放在可捲動的左欄，聊天與開始鈕一直看得到。
- 版本不同（遊戲或資料）的房間在清單上標「版本不同」，不能加入。版本號相同、但規則或資料不同的建置也算版本不同：每個建置有一個規則指紋（`BuildFingerprint.Current`：算對局的 Tribes.Core、Tribes.Session、Tribes.Net 的建置 id（MVID），加上遊戲打包的規則資料（含已安裝的內容包，`client/` 以外，換行符號不計），開機後第一次用到時算一次並印出 `NET rules fingerprint r…`。主機拒絕指紋不同的玩家與觀戰者，對方看到「版本不同，請更新遊戲」。同一份原始碼以同樣方式建置，Windows 與 Android 的指紋相同。

### 房間清單

每個房間一列：房名、模式、人數與延遲，一行說明，以及一個按鈕。對局已經開始的房間名稱前有「對局中」的標記。

| 房間 | 按鈕 | 說明 |
|---|---|---|
| 還在房間裡、有空欄位 | 加入 | — |
| 還在房間裡、欄位已滿、可觀戰 | 觀戰 | — |
| 對局中，這台裝置的部落在裡面（離開過、斷線或還在玩） | 回到對局 | 回到原本的欄位與部落；這種房間排在最前面 |
| 對局中，這台裝置的玩家放棄過 | 觀戰 | 只能觀戰 |
| 無盡模式對局中，主機開放中途加入且有空欄位 | 加入 | 帶一個新部落加入 |
| 對局中，可以觀戰 | 觀戰 | 以觀戰者加入 |
| 舊版主機的對局（不提供名單） | 連線 | 原本的玩家回到自己的部落；其他人能不能加入由主機決定 |

- 什麼都不能做的房間（例如對局中、不開放加入也不能觀戰）不列出。
- 是否「回到對局」以這台裝置的玩家金鑰比對主機公布的名單；名單只有公開 id，看不出金鑰。
- 「輸入位址加入」一直都能用：清單看不到房間時（不同網段、找房的 UDP 被擋），輸入主機的位址照樣可以回到對局。
- 「網際網路」分頁的清單用同一套規則（`RoomListing`）與同樣的按鈕。

### 網際網路房間

「網際網路」分頁（`client/src/Ui/Net/InternetTab.cs`）走 Photon Realtime（[NETWORK.md](NETWORK.md)「網際網路傳輸」）：

- 上方：狀態（連線中、地區與房間數、錯誤）、地區選單、重新整理。地區預設「自動（最近的地區）」，狀態列寫出實際連上的地區；選單的選擇在這次執行中記住。不同地區的房間彼此看不到，朋友要選同一個地區。
- 清單：這個地區的房間，列法與按鈕同區域網路（加入、回到對局、觀戰）。分頁顯示時才連上 Photon、離開分頁就斷開，免得白白占用同時連線數。
- 「輸入房間代碼」：6 個字元（例如 `K7QM2P`），不分大小寫；別的地區的房間在前面加地區（`jp/K7QM2P`）。只打代碼時用清單所在的地區。格式不對時說明代碼的樣子。
- 「建立對戰房間」「建立無盡房間」：在選的地區開房，房間資訊列出房間位址（例如 `jp/K7QM2P`），把它或代碼告訴朋友。無盡房間開放中途加入，主機在對局選單的「邀請」開關照常開關。
- 建立或加入時分頁上顯示「正在建立房間…」「正在加入房間…」並可取消；連上主機（或房間建好）才進入房間畫面。失敗時以對話框說明：連不上伺服器、逾時、設定失效（AppId 不被接受）、伺服器人數已滿、地區無法使用、找不到房間、房間已滿或不開放、主機沒有回應（`multiplayer.internet.error.*`）。
- 對局中主機離開或當機時，其他人由下一位接手繼續（對局畫面顯示「主機換成…」）。主持的這台自己斷線而別人已經接手時，對局存檔並停止，訊息請玩家重新加入同一個房間；在清單上按「回到對局」就回到原本的部落。
- 建置沒有嵌入 Photon AppId 時（BUILD.md「網際網路對戰的 Photon AppId」），分頁說明這個版本沒有網際網路對戰的設定，按鈕停用。
- Photon 的警告與錯誤寫進遊戲紀錄（`PHOTON …`），AppId 已去掉。

### 音樂

`MusicPlayer`（autoload `Music`）依 `data/client/music.json` 的氣氛播放原版配樂：選單與一般遊玩用 `normal`，對局層可切換 `tension`、`combat`。一首播完隨機換下一首（同氣氛有兩首時不連續重複），換氣氛時淡出再淡入。

### 音效

`SoundEffects`（autoload `Sounds`）播放 `data/client/sounds.json` 列出的音效，音量照「音效音量」；同一個音效在它的冷卻時間內只響一次，同時最多 8 個（最久的那個讓位）。選單與面板的每個按鈕按下時都有一聲木魚（按鈕設了 `silent` meta 就不響）。

對局中只有玩家本來就知道的事會響（`SoundCues`）：

| 事件 | 音效 |
|---|---|
| 自己部落的通知：誕生、過世、建築完工、發現敵人、遭到攻擊、建築被摧毀 | `birth`、`death`、`built`、`enemy`、`attack`、`destroyed` |
| 資源不足、建築或村民已達上限 | `denied` |
| 選擇酋長、需要廚師／巫師／武器匠／DJ | `notice` |
| 打中村民、建築或動物，投擲武器（只有在畫面上、而且看得到的格子） | `hit`、`throw` |
| 在地圖上下令移動或攻擊、放下建築或陷阱、跳出提示 | `order`、`place`、`hint` |
| 對局或關卡結束 | `victory`、`defeat` |

除錯版每響一聲印一行 `SOUND 名稱`。

### 開發用命令列參數

接在 `--` 之後：

| 參數 | 作用 |
|---|---|
| `--ui-screen=名稱` | 開機後直接開某個畫面（場景檔名，例如 `campaign`） |
| `--ui-capture=路徑` | 畫面穩定後截圖並結束；`--ui-capture-delay=N` 再等 N 幀，`--ui-capture-linger=秒` 截圖後再停留 |
| `--ui-window=寬x高` | 無邊框視窗，可比桌面還高（直向截圖用） |
| `--resize-to=寬x高` | 畫面穩定後改變視窗大小，再截圖（檢查改大小後的版面） |
| `--boot-hold` | 載入完停在開機畫面 |
| `--ui-lang=en` | 這次以英文顯示，不存檔 |
| `--ui-switch-lang=en`、`--ui-popup` | 設定畫面開啟一秒後切換語言（不存檔）；打開語言清單 |
| `--ui-mission=N`、`--ui-tab=名稱` | 戰役選清單第 N 項（從 0 起）並打開簡報；多人或無盡模式開某個分頁 |
| `--net-region=代碼` | 網際網路分頁這次先選這個地區（例如 `asia`；`best` 為最近的地區） |
| `--net-ui-join=位址`、`--net-ui-host=versus\|endless` | 網際網路分頁連上房間清單後，像玩家一樣加入那個房間，或建立房間（配合 `--ui-screen=multiplayer --ui-tab=internet`；加入後 `--lan-ready` 照樣自動按準備） |
| `--ui-progress=0,1,2` | 戰役清單當作贏過這些關卡來顯示（只在記憶體，不存檔；空白表示都沒贏過） |
| `--ui-saves=資料夾` | 讀取進度畫面改列這個資料夾的存檔（截圖用；刪除也只刪這個資料夾裡的檔案） |
| `--lan-host`、`--lan-join=位址` | 開機後直接建立或加入區域網路房間 |
| `--player-name=名稱`、`--player-id=new` 或 `--player-id=金鑰`、`--colour=N`、`--lan-recolour=N` | 這次使用的名稱、新的或指定的玩家金鑰（同一台電腦開好幾個遊戲時用）、進房選的顏色、進房兩秒後改選的顏色 |
| `--lan-expect=N`、`--lan-autostart`、`--lan-computers=N`、`--lan-quit-after=秒` | 房間人數到 N 才截圖；主機加入 N 個電腦部落（預設 1），等人數到齊、大家都準備好（最多 30 秒）就開始；幾秒後結束 |
| `--session-dev-halls` | 只在除錯版有效。主機開無盡模式的房間時，每個玩家的部落一開始就有蓋好的聯盟會所與多的木頭、石頭（測試聯盟用；寫進開局資料，大家一樣） |
| `--lan-ready`、`--lan-mode=endless` | 加入的玩家拿到欄位一秒後自動按準備；主機開無盡模式的房間 |
| `--lan-snapshot-limit=位元組` | 只在除錯版有效。區域網路主機送出的世界最多這麼大（看世界太大時玩家收到的通知） |
| `--update-check` | 更新畫面一開就檢查 |
| `--ui-reach` | 截圖後檢查畫面上每個按鈕都按得到：夠大的一部分在螢幕的安全範圍內（或捲動清單後在），而且按下去不會落到蓋在它上面的東西；打開的面板、問題框與劇情蓋住的按鈕只計數（`UiReach`，印出 `UI_REACH`、`UI_REACH_PROBLEM`） |
| `--screen-corners=R` | 在 PC 上當作螢幕四角是半徑 R 視窗像素的圓角（看手機的留白版面） |

畫面與房間的變化會印出 `LOBBY …`、`UPDATE …`、`MATCH_REQUEST …` 等紀錄行，安全範圍的邊距在開機與改變時印成 `SAFE_MARGINS`；截圖後的 `UI_EDGES` 列出桌面上視窗最外圈的顏色（只含在螢幕範圍內的部分）。`--ui-capture` 也適用於地圖等非選單場景。

### 開局與推進

- 開啟時讀 `GameApp.Instance.Match`，交給 `MatchConnection.Open` → `MatchSessions.Open`，得到 `IMatchRunner`；讀檔失敗（`SaveFileException`）顯示 `SessionText.SaveProblem` 後回主選單。主機續玩多人存檔時（`Phase == WaitingForPlayers`）蓋上 `ResumeWaitPanel`。
- 戰役的關卡順序只看戰役清單的章節表（`CampaignChapters`，`MatchConnection.Chapters()`）：一關的後半段（關卡 1、6）是前半段在同一個世界裡接下去，規則會自己接，所以不會單獨開始，要求它們時從那一關的起點開始（`CampaignFlow`）。
- 每幀 `runner.Update(秒數)`；規則以原版的 120 毫秒一個 tick 前進（速度 1×、2×、4×），每個 tick 結束後世界視圖畫新的規則幀（`TickRan`），暫停中執行的指令也立即重畫。平滑移動開啟，`RuleFrameSeconds` 跟著目前的 tick 長度。
- 一個人玩時，下列情況讓世界停下（`SetHeld`，tick 以 `TickInput.Paused` 照跑、期間下的指令照樣執行）：暫停、選單（含存讀檔、設定、說明、任務目標）、建造清單與軍隊（原版遊戲選單裡的項目）、提示（含畫面自己顯示的提示 20）、確認框、劇情第一步的開場黑邊、結果畫面。村民名單照原版不停，開著時告訴規則（`RosterOpen`，教學有一步在等它）。多人對局照工作階段的規則（docs/SESSION.md），本機的面板不讓遊戲停下：提示改成訊息列的一行。
- 劇情第一步的開場黑邊（`SceneSlide`）：場景有轉場值（`StoryScene.Transition`）、不是自己版面（種類 27 起）也不是章節畫面時，黑邊照原版每幀 4 行從轉場值合到 164 以上、劇情動一幀、再從負值開到 -48；只有中間那一幀劇情會動，其餘的 tick 都停著（轉場 1、2 都是停 69 個 tick）。黑邊在畫面上照比例合上再打開，期間不顯示文字、點畫面不翻頁。每個 tick 跑完就立刻更新（`TickRan` 在同一個 `Update` 裡），所以停下從下一個 tick 就生效。
- 第 3 關沒有小地圖（原版的總覽地圖在這關不能開）：小地圖鈕與 M 鍵顯示提示 20「有人看到製圖師嗎……？」。
- 音樂氣氛：50 個規則幀內有戰鬥時 `combat`（對戰與無盡模式只算自己部落的戰鬥，觀戰時算任何一個真人部落的；戰役照原版算全世界的），自己部落有集合或全員備戰時 `tension`，其他 `normal`。

### 版面

畫面以邏輯像素排版（`GameApp.FitPixelScale`），每次視窗大小、方向或介面大小改變時重新排列（`MatchHud.Relayout`），世界視圖補滿整個視窗。

| | 橫向 | 直向 |
|---|---|---|
| 上方列 | 整排：人口／居住空間、食物、木頭、石頭、骨頭、庫存武器、軍令圖示；滑鼠時右邊有速度與選單鈕 | 同左 |
| 大按鈕 | 右側一直排 | 最下方一橫排 |
| 選取面板 | 左下 | 大按鈕上方，寬度同畫面 |
| 小地圖 | 右上 | 右上 |
| 訊息列 | 左上 | 左上 |
| 玩家清單（多人） | 小地圖下方，靠右 | 同左 |

- 觸控螢幕（`DisplayServer.IsTouchscreenAvailable` 或 Android）的按鈕約 9 公釐（依螢幕 dpi 與倍率算出，30～60 邏輯像素），圖示整數倍放大；滑鼠時按鈕 24 邏輯像素。觸控時大按鈕是：選單、暫停、建造、軍隊、村民、（無盡模式）部落、多選、小地圖；滑鼠時是：建造、軍隊、村民、（無盡模式）部落、移到選取、小地圖、說明、任務目標。
- 大按鈕一定全部排得下（`ButtonStrip`）：一排放不下時先縮小，最小到約 7.6 公釐（Android 的 48 dp，`HudMetrics.SmallestButton`）；再放不下就排成兩排（橫向是兩欄），按鈕回到原本大小。
- 介面的每個部分都排在螢幕的安全範圍內（見上方「畫面」）；鏡頭的限制與面板置中的範圍都把它算進去。
- 橫向時選取面板寬度是地圖區的 42%（200～320 邏輯像素），但至少寬到一名村民的四個指令按鈕和右上角的 ✕ 排在同一列（`ContextPanel.OrdersWidth`；手機橫向的觸控按鈕約 48 邏輯像素時面板會比 42% 寬）。面板最高長到上方列下面的人數那裡，不會蓋住人數，卡片放不下時在面板裡捲動。
- 鏡頭的限制扣掉介面蓋住的部分（`CameraLimits`）：地圖每一邊都能拉到介面外面；地圖比空出的區域小時置中。

### 鏡頭

- 縮放 0.5～6。滾輪、＋／－鍵以「一個地圖像素剛好是整數個螢幕像素」的級距縮放；兩指捏合連續縮放；空地連點兩下放大一級。
- 平移：單指拖曳、右鍵或中鍵拖曳、方向鍵／WASD、滑鼠碰到視窗邊緣（設定「邊緣捲動」）、點小地圖或拖曳小地圖、點訊息移到訊息說的地方。
- 開局時移到酋長（或第一棟建築、第一個村民）；觸控時一格地圖約 7 公釐寬。對局中加入的玩家拿到部落後（見下方「多人」），鏡頭移到自己的營地一次。

點選以村民與動物實際畫出來的圖判定（`MapPicker`，含平滑移動的位移 `WorldView.MoverOffset`），重疊時取上層的；看不到的地方不會選到東西。順序：點在村民或動物的圖上就是它；否則是畫在那裡的建築——建築的整張圖都算（佔地加上畫在上方與兩旁的部分：屋頂、瞭望塔的平台與上面的守衛，`BuildingShapes` 依物件層的畫法算出每種建築、每個等級的範圍），兩棟的圖疊在一起時取畫在前面的（佔地較下面的；同一列取左邊的），佔地要探索過，指令瞄準的格子是佔地裡離點的地方最近的一格；再來是點的地方旁邊一點的村民（觸控與滑鼠各有容許距離）；最後是那一格的內容。在建築裡面的村民（瞭望塔的守衛、工作中的人）不能單獨選取，點他就是點那棟建築，建築面板列出他們、可以叫出來。村民或動物站在建築前面時先選到它；它已經是選取的東西時，再點一次（不是連點）改選後面的建築，再點又回到它（`TapRules.ShowsAlready`、`MapPicker.BuildingAt`）。對局（對戰、自訂遊戲、無盡模式）裡，其他部落的建築佔地現在都看不到時，地圖上只是記得的樣子：點它算點那裡的地面，不會顯示它現在的狀態；面板裡正在看的其他部落的建築、村民或動物離開視野時，面板收起（`MapPicker.OutOfSight`、`MapPicker.StillInSight`）。戰役照原版，探索過的建築都點得到。選取的單位進建築、死亡或換部落時自動移出選取（`UnitGone`、`UnitDeselected`）。小隊：Ctrl＋1～4 存、1～4 選（連按兩下移過去）。

面板開著時點地圖：會讓遊戲停下的面板（選單、建造、軍隊、說明……）被關掉、這一下不算；提示與結果要按裡面的按鈕；確認框開著時地圖與快速鍵都不動作；村民名單與倉庫開著時地圖照常可以點。從選單打開的存檔、讀取、設定、說明、任務目標關掉後回到選單。

### 戰役、存檔

- 戰役勝利時把該關卡記為完成（關卡 1、6 同時完成關卡 0、5），並把看過的教學劇情旗標存進 `user://progress.json` 的 `tutorialFlags`，下一關開始時帶入。「下一關」直接開下一關（原版也不回選單），「戰役選單」回關卡清單、下一關已開放。失敗後「再玩一次」重開同一關（關卡 1、6 從關卡 0、5 開始）。
- 戰役的結尾照原版：最後一關（第 5 關的後半段，關卡 6）贏了先顯示結果，結果畫面只有「繼續」；按下後結尾劇情（對話 59）在同一個世界、同一張地圖上以章節畫面播出，標題是原版的「劇終」（s.103），插圖是 pi8_09（`GameSimulation.PlayClosingScene`）；播完回到戰役清單，每一關都已打勾。不會開始關卡 7（那是自訂地圖「大湖」）。
- 章節畫面上方顯示原版的標題：那一關的名稱（關卡 1、6 用所屬那一關的名稱），結尾劇情是「劇終」。
- 任務目標依模式：戰役顯示那一關的名稱、開場簡報與最近的劇情；自訂地圖顯示地圖名稱與勝負條件（摧毀敵方所有建築就贏；部落全滅就輸，條件有的話失去第一棟建築也算輸）；多人對戰與無盡模式各顯示一句規則，沒有劇情。
- 存檔由執行器寫（`runner.Save(欄位)`，格式見 SESSION.md）：當下取狀態，寫檔在背景進行，遊戲不會停頓。縮圖存成 `user://saves/<模式>-<欄位>.png`（160×90），由 `ThumbnailShooter` 拍：一個和對局共用 2D 世界的小視窗只畫世界、不畫介面，把畫面中央 16:9 的部分畫成 320×180，下一幀再讀回來，交給執行器 `runner.AttachPicture(欄位, 畫面)` 在背景縮小、編碼、寫入。手動存檔用打開選單時拍的那張；定時自動存檔在寫完後拍當下的畫面（選單開著時用打開選單時那張）；離開對局時先拍好，等離開時的自動存檔寫完再寫縮圖。存檔覆蓋一個欄位時先刪掉舊縮圖，新縮圖寫不出來時這個欄位就沒有縮圖，不會顯示別的存檔的畫面。對局分出勝負後不再自動存檔，縮圖也不換。刪除存檔時連縮圖一起刪（`SaveCatalog.Delete`）。
- 讀檔：先把選中的存檔複製到 `user://saves/.loading.save`（離開對局時的自動存檔可能就是選中的那一個），再以它重開對局畫面。

### 多人

- 本機部落取自執行器（`LocalTribe`、`ViewTribe`），不假設是第 0 個部落；部落顏色取自玩家表（沒選顏色的部落分到沒人用的顏色）。
- 視野（`MatchScreen.FollowViewer`）：在玩一個部落時是 `Viewpoint.Player(LocalTribe)`（自己的部落，加上盟友的視野），其他時候（觀戰、放棄、出局、沒有營地）是 `Viewpoint.Spectator(ViewTribe)`。每個規則幀與玩家表改變時對一次，不同就 `WorldView.SetViewpoint`，小地圖重畫、鏡頭重新限制在新的範圍。中途加入的玩家先拿到的世界還沒有自己的部落（加入的那個 tick 還沒跑），這時看的是第一個真人部落；自己的部落一出現在世界裡，視野、可看的範圍（`MapBounds`）與小地圖就換成自己的，鏡頭移到自己的營地一次（`MATCH_VIEWER`、`MATCH_CAMERA_HOME` 紀錄行）。
- 多人時小地圖下方靠右是玩家清單（`PlayersStrip`）：各部落的顏色、名字（超過 84 邏輯像素以「…」結尾）與狀態（`SessionText.State`：離線、已放棄……），襯一層半透明的深色底；真人在前、電腦在後，最多 8 行，再多時最後一行寫「還有 N 個部落」（`PlayerList`）。清單上方的按鈕（`PlayersToggle`，觸控時是觸控按鈕的大小）與 Tab 鍵顯示或隱藏清單，存在設定的 `ShowPlayers`；小地圖收起來時清單移到小地圖的位置。玩家進出寫在訊息列。觀戰（`LocalTribe` 為 -1 或不能下指令）時上方顯示 `SessionText.Role` 的說明，沒有建造、軍隊、村民等按鈕，地圖仍可自由看。
- 速度與暫停鈕只在 `CanChangeSpeed`、`CanPause` 時出現。
- 訊息列的通知（`NoticeEvent.Tribe`）和提示（`HintEvent.Tribe`）只給那個部落的玩家看；觀戰的人看不到任何部落的通知（`MatchRoom.IsFor`）。
- 無盡模式的消息（`EndlessNewsLines`）：新部落出現（附位置，點一下移過去）、某兩個部落結盟或聯盟結束是給所有人的消息（一方出局時聯盟自動結束，寫成「X 已經出局，你們的聯盟結束了」）；邀請、拒絕、邀請失效、送資源只告訴相關的兩個部落，並依身分寫成「已邀請 X 結盟」「X 邀請你結盟，請到『部落』面板回覆」「X 送來 10 份食物」等。自己的新營地不另外通知。
- 無盡模式的保護期（`data/endless/endless.json` 的 `pacing`：開局 `openingGraceFrames`，之後才來的部落另有 `newcomerGraceFrames`；換算分鐘用遊戲的 tick 長度 `LocalMatchRunner.TickMilliseconds`）：開局或加入時訊息列寫「接下來約 15 分鐘，電腦部落不會來攻擊你」，任務目標面板顯示還剩幾分鐘，結束時訊息列與畫面中央各提示一次「保護期結束了」（`EndlessGrace`）。無盡模式的任務目標標題是「無盡世界」。
- 部落名稱：玩家用自己的名字（沒有名字時叫「部落 N」）；電腦部落只有一個時叫「電腦」，有好幾個時依部落順序編號（「電腦 2」）。
- 無盡模式的建造選單最後是聯盟會所（建築種類 26），圖是 `data/assets/endless/alliance-hall-picture.png`（44×48，跟原版的建造圖一樣是近看的建築加草地），名稱與說明是 `building.alliance.name`／`.desc`；底部的「部落」鈕打開部落面板。
- 中途加入時世界已經沒有空地可以安置新營地（拿到欄位卻沒有部落），會跳出「這個世界已經沒有空地可以安置新的部落營地，你目前只能觀戰。」，之後以觀戰身分留下。

### 建築完整繪製

原版物件層從畫面上方的前一列才開始掃描，佔地在那一列以上的建築即使圖往下伸進畫面也不會畫，於是在畫面上緣看起來只畫了一半（工地最明顯）。對局畫面的世界視圖開啟 `WorldView.WholeBuildings`：物件層多掃描畫面上方 `ObjectLayer.RowsForWholeBuildings`（3）列，任何伸進畫面的建築都完整畫出。開發場景與快照比對維持原版的掃描（預設關閉），畫面仍與原版逐像素相同。藍圖（`WorldOverlay`）每次都整張一起畫。

檢查：
- `tests/Tribes.Client.Match.Tests` 的 `SiteDrawingTests`：所有建築（等級 1、3）與工地放在地形塊邊界兩側，以 4 種畫面大小（縮放 0.5、1、6，直向）讓建築跨過畫面四邊的每一格，共四萬多個鏡頭位置：地形塊（照世界視圖的切塊與邊界）與物件層畫出的每個像素都要和整張地圖一次畫出的相同。另一個測試確認原版的掃描確實會漏畫，以及 3 列足夠涵蓋所有建築圖往下伸出的距離。
- `--site-check`：在實際畫面上（暫停、清出一塊空地）把 13 種工地與建築放在 5 種縮放下、跨過畫面四邊各 4 種程度截圖，與建築置中時比對（依鏡頭實際的位置換算：靠近地圖邊緣時鏡頭到不了要求的位置），所有不隨動畫變化的像素都必須相同；`--site-check-original` 用原版掃描，會出現差異。

### 限制

- 畫面外或視野外的戰鬥沒有聲音，所以聲音不會透露看不到的事。
- Android 11 以前不會回報螢幕圓角，這類手機的圓角只能靠設定的「螢幕邊緣留白」避開。
- 結果畫面的分數照原版乘 10，不加原版的隨機個位數。
- 定時自動存檔與手動存檔的縮圖只有世界、不含介面；離開對局時沒有時間再畫一幀，縮圖是離開前的整個畫面（含介面；從選單離開時是打開選單時那張）。

## 地圖畫面（世界視圖）

`client/src/World/WorldView.cs`（`Node2D`）把規則的 `GameWorld` 畫成原版的地圖畫面：地形、資源點、陷阱、建築（等級、工地、廢墟、揚塵、住戶）、村民（動畫、面向、搬運物、外觀、死亡、建築內的規則）、動物、飛行中的投擲武器、規則觸發的效果、浮動數字與戰爭迷霧，畫法與順序都照原版。組圖全部經過 `Tribes.Graphics`。視圖只讀世界，從不改它；只屬於畫面的狀態（效果清單、浮動數字、投擲弧線、兩個動畫時鐘）放在 `ScenePresentation`。

座標就是這個節點的本地像素：格 `(x, y)` 的左上角在 `(22x, 16y)`，無盡模式的格子可以是負數。鏡頭（`MapCamera` 或任何 `Camera2D`）照常移動縮放，視圖每一幀自己算出畫面上的格子；視窗大小改變（或手機轉向）後，下一幀就以新的大小重組，地形塊補滿整個視窗，地圖外與沒探索過的地方畫成黑色，不會留下沒畫到的區域。新的邏輯大小確定後會發出 `ViewResized` 訊號，畫面在這裡重設鏡頭。`MapBounds` 是鏡頭可以看的像素範圍：戰役與自訂地圖是整張地圖，無盡模式是觀看部落探索過的範圍再往外 4 格；範圍改變時發出 `MapBoundsChanged`。

### 圖層

| 圖層 | 內容 | 更新 |
|---|---|---|
| 地形層 | 每格的地格，加上建築、資源點、陷阱的地面部分；地圖外（無盡模式：還沒產生的土地）是黑色 | 以 16×16 格為一塊在 CPU 上畫成一張貼圖。畫面上的塊每個規則幀檢查一次，只有地格或地面物件變了的塊才重畫；每幀還有餘裕時（3 ms 內）先畫好畫面外一圈還沒有的塊，捲動時通常不必等。記憶體只保留畫面上與外圈塊數的兩倍（至少 32 塊），超過時丟掉最久沒用的，所以鏡頭走多遠都不會一直變多 |
| 物件層 | 原版的物件層：列由上而下（畫面上一列到下兩列）、每列由右而左，逐格畫物件或單位或動物、該格上空的投擲物、該格的迷霧；之前先畫警報與陷阱指令的閃爍格，最後畫效果清單與揚塵 | 每個規則幀、選取改變時重組；鏡頭跟著走時每邊多組畫面外 3 格（`ComposePadding`），鏡頭在這範圍內捲動時沿用，捲出去才重組（`ViewOverride` 時照原版只組指定的格子）；所有圖集合成一張貼圖。組好的部件依順序切成段：同一個移動中的單位、動物或投擲物的部件一段，夾在它們之間的部件一段，每段一個畫布項目；平滑移動時每幀只移動那些段，不重新產生繪圖指令 |

迷霧照原版畫在物件層裡：看過但現在看不到的格蓋部件 12（偏移 −2, −4）；沒看過的格四鄰也沒看過時塗黑，否則蓋部件 11（偏移 −3, −2）。建築的明暗由掃描到它各格時的迷霧逐格決定；看過的建築在看不到時以半迷霧顯示，不會被塗黑。

陷阱照觀看者的視野（見「視野」）顯示：視野裡的部落（自己與盟友；觀戰時是所有真人部落）設的陷阱，以及它們的斥候發現的陷阱看得到，其他部落設的看不到；下令還沒設好的陷阱、集合點標記、警報與陷阱指令的閃爍格只顯示自己的（觀戰時是所有真人部落的）。部落 0 看兩個部落的原版世界時與原版相同。

游標、拉框、建築四角標記、面板、上方列等介面不在視圖裡，由 HUD 畫。原版與選取有關、畫在單位身上的標記（隊伍標記、游標下的陰影、選取單位的生命條與任務圖示、建築的進駐方塊）由 `WorldMarks` 傳入。

對局沒有原版的地圖游標（`CursorCell` 只在重現原版畫面的開發工具裡設定），原版畫給「游標格上的東西」的標記改由選取與滑鼠決定：用滑鼠時是選取的或指著的，觸控時是選取的。

| 原版（`GameCanvas.java`） | 原版的條件 | 對局 |
|---|---|---|
| 村民的任務圖示與生命條（1615–1640） | 選取的、同隊的、游標旁最近的、游標格上的 | `FocusedUnits`（選取）、`HoveredUnit`（滑鼠指著） |
| 建築裡工作的村民的任務圖示與生命條（1622、1635） | 游標指著那棟建築 | `PointedBuildings` |
| 建築的生命條與進駐方塊（2228–2268） | 游標指著（生命條另外在耐久低於一半、升級或修理中、工地時顯示） | `PointedBuildings`：選取的建築，滑鼠時加上指著的（`BuildingFrame.Pointed`） |
| 建築四角標記（2425–2435） | 游標指著 | HUD：選取的建築，滑鼠時加上指著的（`WorldOverlay.MarkedBuilding`、`HoveredBuilding`） |
| 拉框（`w_`） | 從游標拉 | 拖曳拉框（`BoxedUnits`） |
| 對游標格下令、放建築的位置（4245、4375–4469、7897） | 游標格 | 點目標、藍圖跟著手指或滑鼠 |

### 使用方式

```csharp
view.Show(world, viewer: 0);              // 換世界或讀檔後（部落 0 的玩家）
view.Show(world, Viewpoint.Spectator(0)); // 觀戰者：所有真人部落的視野
view.SetViewpoint(Viewpoint.Player(3));   // 換觀看者，不重設畫面狀態、顏色與地形
IFogView fog = view.Sight!;               // 觀看者看得到什麼（小地圖、點選用）
view.OnRuleFrame(systems.TakeEvents());   // 每個規則幀之後，帶這一幀的事件
view.Marks = new WorldMarks { SelectedUnits = selected, FocusedUnits = selected, HoveredUnit = hovered, PointedBuildings = pointed };
view.SetTribeColour(tribe, colour);       // false：別的部落已經用這個顏色
view.SetTribeColours(new[] { 3, 0 });     // 一次設定所有部落（可互換顏色）；有重複就不變
view.SmoothMotion = true;                 // 規則幀之間平滑移動
view.WholeBuildings = true;               // 圖伸進畫面上緣的建築也畫出（對局畫面用；預設照原版的掃描）
```

- 處理的事件：`BlowLanded`（打擊效果與傷害數字）、`HitPointsChanged`（生命增減數字）、`ProjectileThrown`（投擲弧線）。其他事件不影響畫面。
- `ViewOverride` 指定要組的格子範圍（開發場景用來重現原版的視野）；`null` 時跟著鏡頭。
- `RuleFrameSeconds`（預設 0.12）是平滑移動假設的規則幀間隔。
- `ComposePadding`（預設 3）：鏡頭跟著走時物件層每邊多組的格數；0 表示只組畫面上的格子。

### 視野

視圖畫的是一個觀看者（`Viewpoint`）看得到的世界，由 `ViewerSight`（`WorldView.Sight`）決定：

| 觀看者 | 視野裡的部落（`Tribes`、`Includes`） | 迷霧 | 自己的（`IsOwn`：生命條、任務圖示、旗子） | 顯示標記的部落（`ShowsMarksOf`） |
|---|---|---|---|---|
| 玩家 `Viewpoint.Player(t)` | t，以及對局中 t 的盟友（同隊與遊戲中結盟） | t 自己的迷霧：規則已經把盟友的視野與探索過的土地放進去 | t | t |
| 觀戰 `Viewpoint.Spectator(t)` | 所有真人部落（含離線、已放棄），沒有時是 t | 這些部落迷霧的聯集（`CombinedFog`） | 沒有 | 所有真人部落 |

- 視野裡部落的陷阱、斥候發現的陷阱、隱身的單位都看得到；地形層的陷阱與物件層、小地圖、`MapBounds`（無盡模式：視野探索過的範圍再往外 4 格）都依觀看者。
- 每個規則幀 `ViewerSight.Refresh()` 重新找一次視野裡的部落（結盟、退盟、新部落加入），沒變就什麼都不做、不配置記憶體；有變才重建，下一幀重組。換觀看者用 `SetViewpoint`，世界、畫面狀態、顏色與地形塊都保留，只有陷阱看起來不同的地形塊會重畫。
- 多個部落的迷霧（`CombinedFog`）只在讀到時才合併：固定地圖在任一部落的迷霧改變後整張重合一次；無盡地圖逐區塊記住各部落區塊的版本，讀到某區塊時版本變了才重合那一塊（每塊 2 × 64 個 64 位元字），所以費用只跟正在看的區塊數有關，跟世界多大、部落多少無關。只有一個部落時直接讀它的迷霧。
- 對局畫面依玩家身分換觀看者，見「對局畫面」的「多人」。
- 對局裡視野外的建築只照記憶畫（`RemembersBuildings`；記憶由規則記在各部落的迷霧裡，`IFogView.Buildings`）：建築的格子一格都看不到時（`ShowsAsItIs` 為否）不畫它現在的樣子，改畫記得的樣子（`ShowsRememberedAt`：物件層畫上半部，裡面的人、生命條與其他標記都不畫；地形層畫地面部分）；記得的建築被摧毀或換了別的，也照記得的畫到再看到那裡為止；從沒看過的不畫。同一套規則也用在小地圖。對局裡投擲物只畫在看得到的格子，施工揚塵只畫在照現況畫的建築上。戰役照原版：探索過的地方畫建築現在的樣子，投擲物與揚塵照原版畫。

### 無盡模式的地圖

- 地圖由 64×64 格的區塊組成，往四面八方長；四個地形塊並排正好是一個區塊，區塊不會切開地形塊。每塊連外圍 2 格一起畫，鄰格伸進來的部分也畫進去，所以區塊之間沒有接縫；旁邊的區塊後來才產生時，下一個規則幀就把相鄰的塊重畫。
- 還沒產生的土地不畫物件、地形是黑色；沒探索過的地方沒有地圖邊，黑色一直延伸到探索過的土地。
- 物件層的列號是負數時，動畫時鐘用同一個 120 幀週期內的列號，畫法與正數的列相同。
- 部落在遊戲中加入時（`TribeAppeared`），視圖自動替新部落準備外觀，其他部落的顏色不變。

### 部落顏色

8 種固定顏色在 `data/client/tribe-colours.json`，玩家各選一種，8 色還沒用完前不可重複（`TribeLooks.TrySetColour` 會拒絕已被使用的顏色）。超過 8 個部落時（無盡模式）8 色都會用上，其餘部落與別的部落共用顏色；遊戲中新加入的部落拿第一個還沒用的顏色，都用過了就用預設的 `部落編號 % 8`。顏色決定部落的膚色：村民的頭、手腳與軀幹上的皮膚像素換成該顏色的 10 階膚色（亮部到輪廓線），衣服、頭髮、武器不變。

| 編號 | 名稱 | 色票 |
|---|---|---|
| 0 | 琥珀 | `#e9a037` |
| 1 | 赭褐 | `#b37824` |
| 2 | 象牙 | `#f2c8a0` |
| 3 | 赤陶 | `#c8603a` |
| 4 | 橄欖 | `#aaa04c` |
| 5 | 烏木 | `#7c4a2c` |
| 6 | 灰燼 | `#aaa098` |
| 7 | 靛青 | `#6c84bc` |

- 偶數編號的部落穿原版玩家的衣服、奇數穿原版電腦的衣服（頭髮、旗子也跟著）。琥珀是原版玩家的膚色、赭褐是原版電腦的膚色：穿著原本那套衣服時直接用原圖，所以兩個部落都用預設顏色時與原版完全相同。
- 皮膚的位置：手腳取原版電腦換色圖（變體 4）改到的像素；頭與軀幹依底圖的膚色色值，軀幹再分玩家與電腦兩套衣服的區域。其他 6 色的膚色由琥珀的明暗比例套到色票上算出。
- 旗子只有原版的兩種（自己的與其他部落的）。
- 剛出生坐著的嬰兒、小孩的頭像姿勢、躺下與坐下的姿勢取自另一張圖（`pi0_20`），它也是一個皮膚家族，亮部到輪廓的 4 個膚色換成部落顏色；原版電腦部落的這些姿勢用的是玩家的膚色，所以穿電腦衣服、用預設赭褐色時仍畫原圖。
- 單位面板等處的頭像（原版的臉，精靈 720～748）畫的是另一套自己的膚色，`tribe-colours.json` 的 `faces` 列出這些膚色。換色時每個膚色依亮度在玩家膚色的 10 階中找到位置（可在兩階之間），換成該顏色在同一位置的膚色、調到同樣亮度（`TribeColours.FaceSkinMap`）；頭髮、眼睛、腮紅與輪廓不變。玩家部落的頭像原色是琥珀，電腦部落的兩張（27、28）原色是赭褐（`FaceNative`），是原色時照原圖。

無盡模式的聯盟會所（建築種類 26，3×3 格）原版沒有圖，圖片表放在 `data/assets/endless/alliance-hall.png`：3 格並排、每格 66×72 像素，3×3 的地基靠下對齊、上方 24 像素是屋頂。

| 狀態 | 畫法 |
|---|---|
| 建造中 | 共用的 3×3 工地圖（建築種類 16） |
| 完整 | 第 0 格 |
| 受損（生命低於一半） | 第 1 格 |
| 廢墟（被摧毀到揚塵散去前） | 第 2 格，加上原版的倒塌揚塵 |

圖的內容：原版倉庫的石圈、柵欄與空地（原版自己的地面零件），中間是以原版顏色畫的獸皮會所，繞一圈紅色聯盟帶，前方掛著畫有兩個相扣紅環的獸皮旗；受損時獸皮破洞、聯盟帶缺一段、煙孔的一根桿子斷掉、旗子倒下、散落石塊；廢墟是燒黑的空地上塌成一堆的獸皮與桿子，石圈右側崩落。旗杆頂端在左上格往右 4、往上 19 像素（廢墟只剩斷樁，不畫旗子）。圖由 `work/scratch/ui-dev/hallgen` 產生（`dotnet run --project work/scratch/ui-dev/hallgen -- <專案根目錄>`，同時產生建造選單的小圖）。

### 小地圖（無盡模式）

對局畫面的小地圖（`client/src/Match/Hud/MinimapView.cs`）在戰役與自訂地圖照原版的畫法、一格一個像素畫整張地圖。無盡地圖改畫觀看部落探索過的範圍（`MinimapLayout`、`MinimapPainter`）：

- 範圍放得下時以整數倍放大、一格一個像素；比小地圖大時每 2×2 格取中間一格畫一個像素；再大就只畫鏡頭附近的部分（每邊最多是小地圖像素的兩倍格數），隨鏡頭移動。
- 顏色同原版小地圖：觀看者（見「視野」）看得到的地以地形分類上色，看過但現在看不到的較暗，沒去過的是土色；自己的單位黃色、建築橘色（觀戰時沒有自己的）；其他部落的單位與建築（含盟友）用它們的部落色（建築暗 40%），只有現在看得到（建築：看過）的才畫，隱身的單位只畫視野裡部落的。
- 每 4 個 tick 重畫一次，一張圖分 4 幀畫完再換上，每幀的花費只跟小地圖的大小有關，跟地圖多大無關。點或拖曳小地圖時鏡頭移到那一格。

### 平滑移動

`SmoothMotion` 開啟時，單位、動物與投擲物在兩個規則幀之間從上一幀的位置移到這一幀的位置（以整數像素移動，只在位移改變時更新位置）。一次移動超過兩格（進出建築、欄位重用）時直接跳過去。預設關閉。

### 開發場景

`scenes/world/world_test.tscn`，參數接在 `--` 之後：

| 參數 | 作用 |
|---|---|
| `--world=PATH` | 顯示一個世界快照（`.trbw`；開發快照在原版儲存庫的 `original/reference/snapshots/`，不給時顯示其中的 `s4-f06000`）；旁邊有同名 `.json` 時以縮放 1、原版當時的鏡頭與畫面位置顯示，並帶入原版畫面當時的效果、浮動數字與選取標記。視窗是原版的螢幕大小（240×320）時只組原版那一幀的格子，比較大時組滿整個視窗 |
| `--replay=PATH` | 以規則的速度循環播放一段連續畫面（`.trbr`；開發用的在 `original/reference/replays/`），鏡頭可自由拖曳縮放 |
| `--colours=2,5` | 各部落的顏色（依部落順序） |
| `--smooth`、`--zoom=Z`、`--free` | 平滑移動；鏡頭縮放；有 `.json` 時仍用自由鏡頭 |
| `--mission=N` | 第 N 關的開局地圖，沒有單位、全部已探索（大地圖的幀率檢查用） |
| `--match=地圖 --humans=H --computers=C` | 在第幾張自訂地圖開一場自己的對局：H 個人類部落（不下指令）、C 個電腦部落（`--seed=S` 亂數種子） |
| `--endless=種子` | 改開一個無盡世界，部落同上（`--area=N` 起始區邊長，預設 128 格）；`--explore=N` 先產生以觀看部落營地為中心、N×N 格的土地並讓它探索過（不必玩幾個小時就有大片探索過的世界） |
| `--minimap` | 無盡世界時在右上角顯示小地圖（與對局畫面同一張圖），點它移動鏡頭 |
| `--viewer=T`、`--reveal`、`--run` | 視圖屬於哪個部落；該部落已探索全圖（固定地圖）；規則照正常速度跑（沒有 `--run` 時停在開局） |
| `--spectate` | 以觀戰者的視野顯示（所有真人部落） |
| `--teams=A,B,…`、`--allies=A-B,C-D` | 對局各部落的隊伍（依序，-1 沒有隊伍）；開局就結盟的部落對（視野更新後就共享） |
| `--look=T` | 鏡頭一開始在部落 T 的營地上 |
| `--lineup` | 在部落 0 營地旁的空地上，每個部落排一列（用它的顏色）：坐著的嬰兒、小孩、男人、女人、搬木頭的男人、拿棍子的男人、躺著的大人，一張圖檢查所有顏色 |
| `--tour=格數` | 鏡頭以每秒這麼多格的速度在 `MapBounds` 上繞 8 字（捲動時的幀率與記憶體） |
| `--fps-log` | 每兩秒印一行 `WORLD_FPS`：幀率、格數、部件數、組圖耗時、地形最慢一幀（`peak`）、保留的地形塊數（`blocks`）、規則一步的耗時（`sim 最後一步/這兩秒最慢`）、這兩秒的垃圾回收次數（`gc 0代/1代/2代`）、部落數、引擎／貼圖／受控堆積記憶體（MB）；規則在跑時另印一行 `WORLD_SIM`：開始後（略過前 25 步）每一步耗時的步數、中位數、p99 與最大值 |
| `--hide-status` | 不顯示左上角的狀態列（截圖用） |
| `--fill-check` | 底色改成洋紅，`WORLD_FPS` 行另外數出沒畫到的像素（在裝置上轉向時檢查） |
| `--resize-test=寬x高,寬x高,…` | 依序把視窗改成各個大小，畫面穩定後存成 `--resize-out` 目錄下的 `resize-寬x高.png`，印出 `RESIZE_TEST … unfilled N`（沒畫到的像素數）後結束 |
| `--capture=目錄` | 存下連續 `--capture-count` 張畫面（從第 `--capture-start` 張起）後結束 |

### 快照與比對

- `original/reference/snapshots/sSEED-fFRAME.trbw`（原版儲存庫）：翻譯版原版在規則模式下以隨機按鍵（種子 1、4、6，第 80 幀起）玩到該幀、世界更新結束時的世界（`WorldSnapshot`）；`.json` 是原版當時的鏡頭、畫面狀態，以及被介面蓋住、比對時跳過的螢幕矩形。
- `original/reference/snapshots/pokes.txt`：每行 `種子 幀 欄位=值;…`，在該幀畫完後改原版的欄位（用來把鏡頭移到畫面外的戰鬥，例如 `b_I`、`b_K` 與重畫地形的 `z_A=true`）。快照工具與 `reference.sh`（以 DiffHarness 的 `--poke`）都套用，所以兩邊的遊戲仍一模一樣；規則模式下規則不看鏡頭。
- `original/reference/replays/*.trbr`：連續多幀的快照（gzip）。
- `original/reference/frames/sSEED/fFRAME.png`（原版儲存庫）：同一局在 Java DiffHarness 畫出的原版畫面；`terrain.txt` 是 DiffHarness `--check-terrain` 列出的、原版地形緩衝與重畫結果不同的格子。快照、重播檔與這些畫面都含原版的地圖，所以放在原版儲存庫；沒有 `original/` 時，`tests/Tribes.Client.World.Tests` 不編用到它們的測試（快照的繪製與比對），其他照常執行。

```bash
T="dotnet run --project original/tools/Tribes.DevSnapshots --"
$T scan --seed 4 --frames 15000 --every 250                          # 找地圖畫面的幀
$T busy --seed 6 --frames 20000                                      # 找有效果、浮動數字、投擲物、揚塵的幀
$T capture --shots "1:12750,13250;4:6000" --out original/reference/snapshots  # 快照（世界格式或原版程式改了要重做）
$T replay --seed 6 --from 7200 --count 120 --out original/reference/replays/s6-f07200.trbr
bash original/tools/Tribes.DevSnapshots/reference.sh                          # 原版畫面與 terrain.txt
bash original/tools/Tribes.DevSnapshots/godot-shots.sh work/worldview/godot   # 用戶端截圖（先 dotnet build client）
$T compare --actual work/worldview/godot --diff work/worldview/diff  # 逐像素比對地圖區
dotnet test tests/Tribes.Client.World.Tests                          # 不經引擎畫每個快照並與原版比對，另測無盡世界的繪製、地形塊、小地圖與聯盟會所
```

`compare` 與測試只比地圖區：上方資源列以下，扣掉 `.json` 列出的介面矩形。原版的地形緩衝只在格子內容改變時重畫，透明像素保留底下的舊內容，捲動時視野邊緣的格子也會留著視野外的格子畫過來的部分，所以 `terrain.txt` 列出的格子與原版視野最外圈的格子，可能有不屬於現在地形的舊像素。這些位置上、物件層沒有畫到的差異另外計為「地形殘留」，不算畫錯；其他任何差異都算錯。

### 限制

- 這裡的快照是開發用的比對素材（`original/reference/snapshots`），不是玩家的存檔。`original/game/src` 的規則改變後，同一個種子錄下來的遊戲會走向不同，快照與 `reference.sh` 的原版畫面要用上面的 `capture` 重做，並重新挑幀。玩家存檔跨版本的規則見 SESSION.md。
- 原版的地形緩衝與捲動歷史有關（見上），重畫結果一定是乾淨的地形，與原版在那些格子會有少量差異。
- 浮動數字跟原版一樣每畫一次就抖動一次，所以同一個規則幀重畫（例如改了視窗大小）後數字的位置會變。
